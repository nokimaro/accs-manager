## Ключевые решения владельца

**Между планами**
- Коммиты, меняющие только `docs/**` и `*.md`, не запускают CI и не передеплоивают.
- Владелец просил засидировать часть настроек миграцией. Вместо этого значения по умолчанию заданы в коде: `telegram.desktop.*` — это то, что отправляет Telegram Desktop 7.2.9 portable x64. Переопределение админом хранится строкой в БД, сброс возвращает значение по умолчанию.
- Коды берутся **только из @VerificationCodes** (Telegram Gateway), чат 777000 не отслеживается. Код читается из кнопки «Copy», если её нет — регуляркой по тексту.
- Остаток исходных планов 2 и 3 сделан **одним планом 2**.

**План 2**
- Прокси http и socks поддерживаются на равных: спайк с прод-сервера разницы не показал.
- Страну, которую видит Telegram, только показываем, на логику она не влияет.
- Без прокси аккаунт подключается только явным выбором админа. Если прокси недоступен, аккаунт получает статус `proxy_down`, подключения напрямую не происходит.
- Исполнение — **Native**: всё делаю сам в сессии, в конце одно ревью всей ветки.
- Живую проверку разрешено делать на архиве из `tdata-samples/` («Акк из архива не используется никем кроме тебя. Тест безопасен»).

**План 3**
- Вход по номеру со своим api_id («вариант 2»), не забывая про облачный пароль.
- Если аккаунт уже есть в панели, вход отклоняется, как в QR: новая сессия сразу выходит.
- Облачный пароль **хранится зашифрованным и показывается по кнопке**. Сначала владелец сказал «без шифрования», потом выбрал «шифровать, показывать».
- Почта восстановления — необязательный шаг, его можно пропустить. Уже привязанная почта видна в карточке.
- Подход A: вход по номеру — отдельный поток по образцу QR с общим модулем завершения входа. Управление паролем — команды воркеру с ответом.
- «Push deploy verify» — выкатить на прод до живой проверки. Свой api_id/api_hash владелец задал на проде сам.

### Почему Telegram Desktop не подтверждает QR

Владелец не нашёл в Telegram Desktop для Windows способа подключить устройство по QR. По исходникам tdesktop:
- `auth.acceptLoginToken` есть только в схеме протокола и нигде не вызывается;
- ссылки `tg://login` обрабатываются только с `?code=`.

Подтверждать QR-вход умеют только мобильные приложения. Отсюда план 3: стандартный вход по номеру, при котором код приходит в открытый Desktop сообщением от «Telegram».

## Уроки и грабли

- **mtcute:**
  - после `connect()` и `getMe()` обязательно `client.notifyLoggedIn(me.raw)`, иначе нет цикла обновлений;
  - `client.start()` на мёртвой сессии уходит в интерактивный вход;
  - методы входа (`sendCode`, `resendCode`, `signIn`, `checkPassword`) и `client.call` принимают `abortSignal`;
  - регистрация новых номеров не поддерживается (`MtUnsupportedError`).
- **Telegram:**
  - Desktop не подтверждает QR;
  - у свежей сессии смена пароля упирается в `SESSION_TOO_FRESH_%d` (ждать часы);
  - текст `EMAIL_UNCONFIRMED_%d` несёт длину кода;
  - адрес почты восстановления Telegram отдаёт только при известном пароле.
- **Drizzle:**
  - опциональный peer `better-sqlite3` у `@mtcute/node` порождает вторую копию drizzle, поэтому операторы импортируются только из `@workspace/db`;
  - `drizzle-kit generate` чувствителен к скрытому hoist pnpm.
- **BullMQ:** `removeOnComplete: true` вместе с `waitUntilFinished` даёт гонку («Missing key for job») — завершённые задачи держать хотя бы недолго.
- **Docker Compose:** `up --wait` требует healthcheck у каждого сервиса, `healthcheck: disable` ломает деплой.
- **Тесты:**
  - случайные значения в уникальных полях дают редкие падения — использовать счётчики;
  - под полной нагрузкой гейта всплывают гонки, которые в изоляции не видны.
- **Гейт:** `команда | tail` скрывает код выхода. Проверять реальный код (вывод в файл, затем `echo $?`), прежде чем коммитить.
- **zsh:**
  - не разбивает на слова переменную без кавычек (`for a in $list` даёт одну итерацию);
  - `====` в командной строке — ошибка.
- **Cloudflare** отвечает 403 на user-agent `Python-urllib`.
- **Правило «один auth key — одно место»** закреплено в AGENTS.md: перед переносом tdata в другое место — пауза или удаление без выхода.
